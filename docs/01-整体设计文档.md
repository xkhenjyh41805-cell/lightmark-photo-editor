# 光印 LightMark — 对话式 Agent 修图产品整体设计

> 版本：v0.2（更新为对话式 Agent 定位）
> 日期：2026-10-13
> 状态：桌面修图 Demo 已实现；真实多模态 Agent、参考图风格匹配和移动端仍在规划

---

## 一、这个软件要解决什么问题

你是一个摄影爱好者，拍完照片不知道从哪里下手修。市面上的软件分两类，都不太适合你：

- **专业软件**（Lightroom、Photoshop、Capture One）：功能强大但门槛高，打开一脸滑块不知道每个干啥、该调多少。
- **手机修图 App**（Snapseed、VSCO、美图秀秀）：好用但靠滤镜一键套用，你学不到东西，调完也不知道为什么这样调。

我们要做的，是**第三条路**：用户通过对话表达修图目标，Agent 理解当前照片和上下文，调用传统、非生成式工具主动修图；同时解释做了什么，并提出可采纳的后续建议。用户可以继续追问、要求调整、查看参数、撤销操作。

核心一句话：**用户与 AI 对话，Agent 调用工具修图，也主动提出建议；用户始终看得见、能调整、可撤销。**

## 二、你是谁、做到什么程度算成功

- **使用者**：会拍照、不太会修图的摄影爱好者。重点是"你自己"先能用、用得顺。
- **成功标准**：
  1. 打开软件能导入照片，看到专业修图软件该有的东西（直方图、滑块、前后对比）。
  2. 能通过自然对话让 Agent 调用工具完成修图，知道改了什么、为什么，并能看到可采纳的后续建议。
  3. 调完能导出，画质不损失。
  4. 流程能切换：纯新手用简化流程，想进阶时切到专业流程。

不追求替代 Lightroom，追求的是"带你入门 + 陪你修图"。

## 三、软件长什么样（界面草图）

```
┌──────────────────────────────────────────────────────────────┐
│  菜单栏：文件  编辑  视图  帮助            [新手模式 ▼] [导出] │
├────────────┬────────────────────────────────┬────────────────┤
│            │                                │  右侧：调整面板  │
│ 左侧：     │                                │                │
│ 图库       │       中间：图片预览区          │ ▼ 基础校正      │
│ ─────      │     （可前后对比、放大）        │   曝光  ──●──   │
│ 照片1.jpg  │                                │   对比度 ─●──   │
│ 照片2.jpg  │                                │ ▼ 影调          │
│ 照片3.jpg  │                                │   高光  ─●──    │
│            │                                │   阴影  ──●──   │
│            │                                │ ▼ 色彩          │
│            │                                │   ...           │
│            ├────────────────────────────────┤                │
│            │ 底部：直方图 + 前后对比        │                │
│            │ 💬 Agent：执行结果／可采纳建议 │                │
├────────────┴────────────────────────────────┴────────────────┤
│  底部步骤栏：① 导入 → ② 基础校正 → ③ 影调 → ④ 色彩 → ⑤ 导出    │
└──────────────────────────────────────────────────────────────┘
```

三个区：

- **左边图库**：管理你导入的照片，点哪张修哪张。
- **中间预览**：大图显示，能看到调整效果，能按住键看原图对比。
- **右边调整面板**：所有滑块按流程分组，新手模式下每组只露最关键的几个。

辅助信息与 Agent 交互入口也很关键：

- **直方图**：那张山一样的图，专业修图看它判断曝光。我们会做成"会说话的直方图"，鼠标移上去告诉你哪一段代表什么。
- **Agent 对话侧栏**：用户描述目标，Agent 可调用修图工具执行安全操作，也能解释结果、追问不清楚的意图并主动给出可采纳建议；已执行动作和未执行建议要明确区分。

## 四、核心流程（软件的骨架）

修图按顺序走这几步，每步对应右边面板一组滑块：

| 步骤 | 干什么 | 典型滑块 | Agent 如何理解、操作或建议 |
|------|--------|----------|-------------------|
| ① 导入 | 把照片放进软件 | — | 自动判断是 RAW 还是 JPG，提示 |
| ② 基础校正 | 先把底子打正 | 曝光、对比度、白平衡 | 直方图是否溢出、色温是否偏 |
| ③ 影调 | 调明暗层次 | 高光、阴影、白色、黑色 | 高光是否过曝、阴影是否死黑 |
| ④ 色彩 | 调颜色感觉 | 饱和度、自然饱和度、HSL | 整体偏色、某颜色是否太跳 |
| ⑤ 细节 | 锐化、降噪 | 锐化、降噪 | 是否有噪点、是否够清晰 |
| ⑥ 局部（进阶） | 只调一部分 | 渐变滤镜、径向滤镜、笔刷 | （后续版本）|
| ⑦ 导出 | 存成成品 | 格式、尺寸、画质 | 给出导出参数建议 |

**新手模式 / 专业模式切换**：

- 新手模式：只露每步最核心的 2-3 个滑块；Agent 用口语说明执行结果，并给出少量清楚的可选建议。
- 专业模式：露出全部滑块（对标 Lightroom 的完整面板），Agent 建议带具体数值和原因，并可展开查看执行计划。

切换是无缝的，调过的参数都保留。

## 五、Agent 如何逐步落地

产品方向是对话式 Agent，而当前项目仍是桌面修图 Demo，尚未接入真正的多模态模型。实现按阶段推进：

1. **保留现有本地规则建议：**基于直方图等规则提供即时提示，但明确标记为“规则建议”，不伪装成看图大模型或 Agent。
2. **接入多模态模型后：**用户围绕当前照片多轮沟通；Agent 将意图转换成受限 EditPlan，调用白名单内的传统修图工具执行安全调整，并解释参数变化。对不确定区域、超范围操作或高影响行为应追问／请求确认。
3. **把主动修与建议分开呈现：**已执行的调整进入可撤销编辑历史；Agent 发现的其他改进方向显示为单独建议，用户选择后才执行，不与已完成操作混淆。
4. **参考图风格是后续能力：**用户选择一张参考照片后，模型尝试提取可由现有色调／色彩参数表达的风格特征，形成可调整、可预览的参数配方；不做图生图、像素搬运或内容替换，质量和可行性仍需验证。

模型 API、工具白名单、对话 UI 和图像引擎彼此分离。用户自接多模态模型是首版方向；图片发送需授权，模型不得执行任意脚本、覆写原图或自行导出。后续如提供内置模型，也通过同一 `VisionProvider` 接口接入。

## 六、技术选型（用什么工具做）

| 部分 | 选什么 | 为什么 |
|------|--------|--------|
| 桌面框架 | **Electron** | 用网页技术（HTML/CSS/JS）做桌面软件，生态成熟，资料多，你将来好理解。以后想转网页端，代码能复用大半。 |
| 前端界面 | **React + Tailwind CSS** | 界面组件化，好维护。Tailwind 写样式快。 |
| 图像处理 | **Canvas / WebGL + 可能用 sharp 库** | 滑块实时预览用 Canvas/WebGL，导出用 sharp 保证画质。 |
| 本地存储 | **SQLite 或纯文件** | 存图库信息、修图历史。轻量。 |
| 打包发布 | **electron-builder** | 打成 Windows 安装包，双击能用。 |

> 备选：Tauri（比 Electron 轻很多，但用 Rust，对你来说后续维护门槛高）。先用 Electron。

这套技术栈的好处：**全是 JavaScript 生态**，你将来想自己改点什么，查资料、问 AI 都容易。坏处：打包出来的软件体积大（Electron 通病，100MB+），对个人软件无所谓。

## 七、分几个阶段做（开发路线图）

### 阶段 1：能看图（1-2 个工作单元）
- 搭好 Electron + React 项目骨架
- 能导入一张照片显示在中间
- 左边图库能列出来切换

### 阶段 2：能调图（核心，2-3 个工作单元）
- 右边做出第一组滑块（曝光、对比度、高光、阴影）
- 拖滑块图片实时变
- 底部直方图实时跟着变
- 前后对比（按住看原图）

### 阶段 3：能引导（2 个工作单元）
- 步骤栏 + 新手/专业模式切换
- 内置规则算法给提示（"高光溢出"这种）
- 每个滑块加悬停说明（这个滑块干啥用的）

### 阶段 4：能导出（1 个工作单元）
- 导出 JPG/PNG，选画质尺寸
- 保存修图参数（下次打开还在）

### 阶段 5：接 AI（后续）
- 规则算法 → 真正的 AI 建议
- 更多进阶功能（局部调整、预设等）

每阶段做完你都能看到一个能用的东西，不会等到最后才看到成果。

## 八、相关开源项目参考

我们在做的过程中会参考这些开源软件的思路（不是直接抄代码，学设计）：

- **darktable**（开源，对标 Lightroom）：专业的 RAW 修图流程参考。界面复杂，我们学它的流程划分，不学它的复杂度。
- **RawTherapee**（开源）：同样专业，影调和色彩处理算法参考。
- **digiKam**（开源）：图库管理参考，照片组织方式。
- **Photopea**（在线，部分开源）：浏览器里的 Photoshop，界面交互参考。

这些项目都是给专业人士用的，太重。我们做的是**"减法版 + AI 教学"**，定位不同。等开始做时，我会按需翻它们的实现思路。

## 九、目录结构预想（将来代码怎么放）

```
ai-photo-editor/
├── docs/                  ← 文档放这（你现在看的就是）
├── src/
│   ├── main/             ← Electron 主进程（管窗口、文件）
│   ├── renderer/         ← 界面（React）
│   │   ├── components/   ← 界面组件（滑块、直方图、图库等）
│   │   ├── panels/       ← 调整面板（基础校正、影调…）
│   │   └── store/        ← 状态管理
│   ├── image/            ← 图像处理核心（滑块算法、直方图计算）
│   └── advisor/          ← AI/规则建议模块（将来换 AI 只动这里）
└── package.json
```

关键：`advisor/` 单独拎出来，这就是为"先做基础、后接 AI"留的口子。
