# 人脸与交互式分区工具评估

日期：2026-10-25  
状态：能力与许可初筛；不是最终模型选型，也没有把任何工具接入 LightMark。

## 当前结论

“详细分区”不是一个模型能同时可靠完成的单步任务。比较稳妥的工具链是：先找出每张脸及其在照片中的位置，再由脸部解析器提供皮肤、眉眼、嘴唇等语义区域，最后用用户点选/笔刷提示式分割修正具体边界。Agent 负责理解“左边那个人的脸暗了”等意图，引用应用已经生成并通过检查的区域，再提出局部参数；像素级蒙版由可替换的分割 provider 生成或修正。Agent 不应直接自由输出一张蒙版，也不应把参数悄悄回退成全图调整。

目前没有核实出一个既可直接商用发行、又提供全脸部件分割、又适用于复杂真实摄影照片的单一模型。需要把“源代码许可证、预训练权重许可证、训练数据条款、服务商数据条款”分别检查，不能只看 GitHub 仓库标出的许可证。

## 能力短名单

### 1. 人脸实例定位与几何先验：MediaPipe Face Landmarker

Google 的 Face Landmarker 对每张检测到的脸输出面部网格、3D 关键点和可选表情系数/变换矩阵；模型包说明包含最多 478 个面部关键点。它能帮助区分一张照片中的多张脸，并为眼、唇等区域提供几何提示，但文档没有把它描述成皮肤/眼睛/嘴唇像素蒙版生成器。[1]

因此可作为“定位脸、关联人物、给后续解析器提供提示”的候选，不应单独宣称完成精细语义分区。MediaPipe 源码仓库采用 Apache-2.0，但 Face Landmarker task model 是独立模型资产；集成前仍要核对具体模型文件及随包分发要求。[2]

### 2. 人脸部件语义分割：BiSeNet / face-parsing

`yakhyo/face-parsing` 提供 BiSeNet 的人脸解析代码、PyTorch 与 ONNX 推理流程，列出的类别包含皮肤、头发、眼睛、眉毛、嘴唇、鼻子、眼镜等；仓库源码许可为 MIT。[3]

但该仓库说明模型在 CelebAMask-HQ 上训练。该数据集官方协议明确限定为非商业研究用途，并禁止将图像或衍生数据用于商业目的；Hugging Face 上一个常见的 CelebAMask-HQ 微调模型也标注为非商业研究和教育用途。[4] [5] 所以“代码是 MIT”不能证明相应预训练权重可用于商业产品。当前只将其列为研究/隔离评测候选，不进入 LightMark 发布版本，除非权重及训练数据权利得到单独澄清。

另一项值得比对的是 EasyPortrait。项目公开了全脸解析与人像分割权重及 9 类标注（包括皮肤、眉毛、左右眼、嘴唇、牙齿和人物），其 GitHub 仓库标示 CC BY-SA 4.0，而不是 Apache/MIT。其对闭源桌面软件、预训练权重再分发和模型衍生物的具体义务应进一步做许可证审查，未审查前也不作为已批准依赖。[6]

LaPa 的情况类似：GitHub LICENSE 文件为 Apache-2.0，但数据集 README 同时明确限制数据只能用于非商业用途。仅凭代码仓库 LICENSE 不能得出 LaPa 数据或基于它训练的权重可以商用的结论。[7]

### 3. 交互式边界修补：MediaPipe Interactive Segmenter 或 SAM 2

MediaPipe Interactive Segmenter 是通用交互式分割工具：先设置一张图片，再输入表示兴趣位置的点/笔刷 strokes，返回每像素为目标的置信权重图；新版接口允许复用图像特征，多次输入提示。它能支撑“点一下目标、再补画/擦除”的交互闭环，但它不理解“人脸/头发/嘴唇”这样的语义名称。[8]

Meta SAM 2 同样支持图像上的点和边界框提示，并提供自动蒙版生成；官方仓库许可证为 Apache-2.0。它适合根据检测框、面部解析边界或用户提示细化单个目标，但不负责告诉 Agent 哪一块语义上是皮肤或眼睛。[9]

Roboflow 文档提供 SAM 2 的 Serverless Cloud API，先生成/缓存图像嵌入，再通过点和框提示请求分割；也支持自托管服务。云端模式会把图像发给外部服务，必须独立完成服务条款、留存、费用和授权检查；本地/自托管方式不必因此把照片交给云 API。[10]

MediaPipe 的官方代码示例 Apache-2.0、SAM 2 仓库 Apache-2.0，都不应被误解为所有模型资产、托管服务或输入图像数据条款自动相同。逐个核实具体模型文件和服务端条款仍是集成门槛。[2] [8] [9] [10]

## 对 LightMark 的建议

保留可替换的 `FaceLocator`、`FaceParser`、`MaskRefiner` provider 能力，不把模型名写进 Agent 工具协议。OpenAI 兼容的大模型只负责意图理解与区域 ID 选择；图像区域服务由 LightMark 本地调度。可选云端 provider 与多模态 Agent 图片授权分开询问，任何模式都不能绕过本地确认、候选预览、擦除/补回、撤销和失败提示。

第一轮实验建议分别验证：

1. 多人照片中每张脸是否被分别定位并稳定关联；
2. 眼、眉、嘴唇等类别的像素边界是否足够适合局部曝光/色彩参数；
3. 侧脸、眼镜、遮挡、头发压脸、低分辨率和不同肤色的误分情况；
4. 点选/框选修正一次需要多少交互，以及修正后是否破坏语义标签；
5. 每个模型代码、权重、数据集和云端服务的商业/再分发边界。

在许可证门槛通过前，可用合成或明确授权并人工标注的照片做技术验证；不因公开权重“能跑”就决定随软件发布。若权重许可始终不能确认，后续方向应是寻找取得明确商用授权的供应商，或使用权利清晰的数据训练/委托训练，而不是把非商业研究模型打包进产品。
