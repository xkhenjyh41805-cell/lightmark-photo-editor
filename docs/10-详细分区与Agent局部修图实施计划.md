## 1. 产品目标与不可突破的原则

用户导入一组照片后，可按需获得可被 Agent 准确引用的语义区域。首要目标是人像，尤其是“具体哪一个人、那个人脸/皮肤/眼睛/眉毛/鼻子/嘴唇/头发”等局部；之后扩展宠物、服装、天空、背景及其他对象。用户说“把左边那个人脸提亮”时，Agent 应先将描述解析为当前照片中的一个明确区域，再把非破坏性的参数调整绑定到该区域，而不是误改全图。

- 不做生成式重绘、补画或改变照片内容；分区和参数调整都必须可检查、可撤销。
- 人像与照片默认留在本机；调用用户选定的多模态 API 或云端分割服务时，逐次明确说明图像发送对象和范围，不能暗中上传。
- Agent 可解释现象、提出建议、识别用户所指区域并组织工具调用；目标不明确时先澄清。建议和已执行改动要区分，未授权前不得悄悄套用局部参数。
- 低质量分割不得静默采纳。蒙版候选需有预览、接受/拒绝、擦除/补回、撤销和失败提示。
- 模型/服务以 provider 能力接口接入，不把应用绑定到单一 LLM、云厂商或一个分割模型。开源项目仍需记录代码、权重、数据集与服务条款，不能只看仓库首页徽章。

## 2. 名词：语义区域、蒙版、调整层

| 对象 | 直观含义 | LightMark 中的职责 |
|---|---|---|
| **语义区域 Region** | “右边第二个人的脸”“皮肤”“天空”等可被人和 Agent 指代的对象 | 稳定的 `regionId`、语义标签、实例/人物关联、范围、状态与来源；供 Agent 选择 |
| **蒙版 Mask** | 图片每个像素属于目标的程度/权重图，硬边可为 0/1，柔边可为 0–1 | 说明某个 Region 在哪些像素上生效；可由模型生成，也可点选、笔刷、羽化修正 |
| **局部调整层 Adjustment Layer** | 一组曝光、色彩等编辑参数及其生效范围 | 保存调整值并引用 `regionId`/`maskVersion`；不复制或改写原始像素 |

三者需要区分，但需建立明确引用关系：一个语义区域可有一个或多个蒙版版本；一个局部调整层引用选定区域及蒙版版本；同一区域可叠加多个可撤销调整层。类似线性渐变、径向渐变、笔刷，本质上也是蒙版/选区的不同生成方式，不等同于整个调整层。现有局部调整引擎可继续承载参数运算，新增 Region/Mask 数据用于确定作用范围。

## 3. 导入时的分区选择体验

每次导入单张或文件夹/图库组，可选择以下模式；具体模式默认值尚未最终定案，不在没有验证前将任何模式设为强制：

1. **不分区：** 不预先生成语义蒙版。用户仍可要求 Agent 按需生成局部区域或手工创建蒙版。
2. **粗分区：** 只尝试较大区域/对象（如人物、背景、天空等）。先产生候选，不代表可直接应用；任何类别须由实际样片验收后才可作为可用候选。
3. **细致分区：** 尝试人物/人脸/皮肤/五官/头发等细粒度区域，成本、时间和失败风险更高；显示分析进度及缺失/低可信区域。
4. **Agent 推荐：** 根据用户所选模型的图像理解或本机可用分析，解释“为什么建议粗/细/不分区”，再由用户确认。本地与云端分析分开标示；推荐不能自动触发未授权的云端图像请求。

允许用户为单次导入作选择，或在设置中保存偏好并保留每次关闭的入口。首版可用“记住我的选择”代替复杂习惯学习；只有用户明确同意后，才考虑依据重复行为推荐。导入动作、分区任务和图库分组/对话的关系继续沿用现有产品定义：导入一组图库形成持续工作组；单张和文件夹导入均属于该组工作流。

## 4. 建议的处理架构

```text
导入照片/文件夹
  -> 用户选择不分区/粗分区/细分区/查看 Agent 推荐
  -> 可选图像理解：LLM 只返回受 schema 限制的对象/部位描述、框或提示点
  -> 本机/用户选定的分割 provider 生成候选像素 mask
  -> Region 与 Mask 候选写入可追踪缓存，显示预览
  -> 用户确认/拒绝/正负点或笔刷修正
  -> Agent 将自然语言目标映射到已确认 regionId
  -> 生成绑定该 Region 的局部 Adjustment Layer 预览
  -> 用户确认后加入历史栈；可撤销/重做；导出时仅渲染非破坏性参数
```

职责分开：

- **Vision Agent / 多模态 LLM：** 识别人、部位、用户指代、图像现象，给出框/点等结构化提示或在已有区域中选 `regionId`。模型可用性、图像输入和 API 授权由用户配置。
- **FaceLocator：** 找出脸/人物候选和实例关联；关键点/几何输出不是皮肤像素蒙版。
- **FaceParser：** 产生语义部件候选，如 skin、eyebrow、eye、nose、lip、hair；必须按部件标签与人工真值评估。
- **MaskRefiner：** 接收框、正/负点、笔画或已有 mask，提供交互式边界修正。
- **LightMark 调度/适配层：** 负责能力协商、坐标换算、候选缓存、尺寸/模型版本记录、取消、错误和超时处理；统一转成内部 Mask 格式。
- **Adjustment Engine：** 只应用已确认的参数和区域范围；原始照片不被蒙版服务或 Agent 直接覆盖。

可替换的能力接口（方案，不是已接入 API）：`FaceLocator.locate(image)`、`FaceParser.parse(image, hints?)`、`MaskRefiner.propose/refine(image, box?, positivePoints?, negativePoints?, strokes?, priorMask?)`。Agent 与分割后端可由不同供应商提供；服务能力、网络位置、授权与成本须在调用前清楚呈现。

### P1b：多模态模型区域提示探针（单图能力探针，非分割验收）

- 通过用户当次明确授权的 LightMark 当前配置接口测试，在一张 `OIP (2).webp` 上取得可解析的人脸及部位框；较长 JSON 请求曾被现有 token 上限截断，精简请求返回了脸、皮肤、左右眼、左右眉、鼻、唇、头发等归一化框。
- 已新增 `src/agent/regionHints.ts` 严格解析器：验证 JSON/坐标范围，不信任自报置信度，并把结果标成 `needs_review`。测试不产生像素 mask，不会自动采纳。
- 实验只说明模型可提供某些定位线索；一张照片不能证明多人物排序、遮挡、侧脸或部位边界能力。API 调用可能收费；任何再次发送图像到 API 的尝试都须另行取得明确授权。

### P1c：人物候选模型评测（评测已完成；没有生产模型被批准）

- COCO val2017 固定分层子集：200 张、796 个非 crowd person 标注，包含单人、2–4 人、5+ 人、小人物、猫狗负例及其他负例；比较 RTMDet-Ins-tiny ONNX、YOLO26n-seg ONNX、RTMDet-Ins-S。
- mask IoU≥0.50 的总体 F1 分别为 0.689 / 0.699 / 0.719；IoU≥0.75 的 F1 分别为 0.414 / 0.487 / 0.458。RTMDet-S 总体/小人物召回较高，但 CPU 单张中位数约 1.27 秒；拥挤场景 FP 多。数据是 COCO 子集，不是产品性能或真实摄影的保证。
- 用户提供的四张远景/遮挡图在 Tiny、YOLO 与 RTMDet-S 同图对照：三者都把大面积荷叶并入人物蒙版；竹干交界仍有污染/不确定性。小人物和双人实例有时可分开，不足以证明质量可靠。**三种模型均不批准进入生产人物分区，不自动应用。** YOLO26n-seg 仅作 AGPL 隔离研究对照。

### P1d：交互式分割与人脸细分 POC（已试验，未达质量门槛）

- MediaPipe MagicTouch 只在旧比较图裁出的 760×1140 派生预览上作低分辨率 smoke test；一次正点约 40.6 秒，正/负点约 46.2 秒，二值 mask 覆盖约 50.7%/47.7%。此结果不代表原始照片效果，也没有解决语义脸部部件分割。
- MobileSAM vit_t 对原始 2000×2999 照片，用多模态模型提供的脸/部位框各生成 3 个候选，共 27 个。内部最长边仍缩至 1024。face 与 skin 最佳候选 IoU 为 0.994，几乎相同；眉候选不稳定，鼻候选分歧明显。眼/唇候选看起来较集中，但没有像素级真值。
- 2026-10-26 本机正负点追加实验：box-only 皮肤候选面积约 2.228%；加脸颊正点后约 2.234%，与基线 IoU 0.994，几乎没变化。增加双眼/嘴唇负点时，只有一个较低分候选排除部分提示点；高分候选仍包含这些点。增加双眉/遮挡叶片负点后，最高分候选仍包含眉/唇提示位置，只有个别候选排除双眼和叶片。**提示能影响候选，但目前无法稳定满足语义排除条件；分数不等于准确率。** 原片 hash 前后相同，脚本零 API 请求，候选未采纳。

### P2：建立人工像素级评测集（下一阶段）

1. 选择 5–10 张经用户允许用于本机评测的照片，涵盖正脸/侧脸、多人、遮挡、眼镜、远景小脸、不同光照和发际线；用户照片默认仅本机处理。
2. 逐张记录人物数量、左右/前后目标指代，以及允许评测的语义类；若缺少可用脸部细节，不以模型框自动补成“真值”。
3. 人工标注 GT：face、skin（明确规定眼/眉/鼻/唇是否属于 skin，建议眼睛/眉毛/嘴唇单独并从 skin 排除）、eyes、brows、nose、lips、hair；标注叶片/头发等遮挡边界和不可见区域策略。
4. 对 RTMDet/Tiny、专用 face parser、SAM/MobileSAM 或 MediaPipe 交互分割进行同图盲评；像素级 IoU/Dice、边界 F-score、误纳/漏纳面积、每人/每部位召回分开报告。候选一致性和模型分数只作诊断项，不替代 GT。
5. 记录推理时间、冷启动、内存、图像内部编码分辨率和高分辨率边缘限制；对每个代码、权重、训练数据及模型文件记录来源和许可。未澄清的数据/权重只在隔离研究 POC 中使用，不自动打包。

### P3：选定 provider 与边界质量门槛（P2 后）

- 先决定哪些区域类别确实有用户价值及可用真值；对 FaceLocator、FaceParser、MaskRefiner 分别评估，避免选一个“全能模型”硬做所有类别。
- 根据人工 GT 与用户工作流设定正式阈值。初始讨论建议（**未获用户确认，不是现行验收标准**）：清晰正脸大区域 IoU 至少 0.90；细小五官区域 IoU 至少 0.80 并同时看 Boundary F-score；明确语句的 Region 指代命中率至少 95%；所有模糊情况需澄清而不是猜。最终标准应通过标注集和实际编辑试用修订。
- 只有达到门槛且许可/运行环境可复现的类别，才能标记为“可用候选”；仍要求用户确认是否创建/应用。

### P4：区域候选与蒙版审核 UI（达到 P3 后）

- 在画布/侧栏提供区域清单、每个人物实例编号/位置、部件类型、可见/遮挡/失败状态和来源；点击条目可高亮蒙版，支持显隐与局部预览。
- 提供按区域查看多个候选、选择/拒绝、正/负点、画笔补回/橡皮擦除、羽化、清空/重置等工具。对遮挡物、边界不确定和尺寸过小情况给出明显提示。
- UI 显示分区模式、处理位置（本机/云端）、所用 provider、耗时和是否发送图片；云端请求前单独授权，失败可取消或转手工。

### P5：区域绑定的非破坏性局部调整

- 扩展已有局部调整数据，使 `AdjustmentLayer` 明确引用 `regionId` 与 `maskVersion`；候选更换后不得静默改变既有调整的作用范围。
- 支持把曝光、色温、色调、对比度、饱和度等局部参数以独立历史事务应用到该区域；渲染仍走现有非破坏性图像管线，sidecar 向后兼容。
- 将“蒙版编辑”和“参数编辑”分开撤销/重做；撤销 Agent 提案时参数不能在后续消息重新出现，跨照片/图库时状态关联正确。

### P6：Agent 区域选择与安全工具协议

- Agent 先获得当前照片已确认 Region 的简短列表（稳定 ID、类别、实例位置、审核状态），再把“左边那个人的脸”等指代映射到 Region；不得把模型输出的临时坐标当作已确认区域。
- 若存在多个匹配对象、用户所说部位未生成、区域尚未确认或多个模型分歧，先展示候选/询问用户；不回退成全局调整。
- 工具边界分为 `list_regions`、`propose_region_analysis`、`refine_region_mask`、`propose_adjustment(regionId, params, reason)`、`commit_adjustment`。修改像素的动作由白名单图像工具处理；用户确认后才提交，结果自动进入撤销历史。
- Agent 回复说明“观察到什么 / 为什么这样建议 / 目标区域 / 修改参数”，执行结果与独立建议分开呈现。

### P7：导入、批处理与偏好（主流程稳定后）

- 导入支持单张与文件夹，并归入一组图库工作/对话。按用户所选模式排队分区，支持进度、取消、失败重试和按照片跳过。
- 不默认删除、移动或导出照片；自动分区不等于自动修图。批次同参/逐图归一等问题与此项目阶段分开验收。
- 记录用户对模式的偏好可帮助 Agent 推荐，但“推荐”始终允许用户改选，首次授权 + 每次可关闭的原则继续适用。

3. **继续比较交互提示是否值得进入 UI：** 需要的是可控的候选预览和人工笔刷修边，而不是指望 Agent 一次猜中每个像素。多张图验证完成后再确定 P3 质量阈值。
4. **暂不改主流程、不接云端分割、不调用多模态 API、不自动应用蒙版。** 再次发送照片或启用云端分割前，另行确认具体服务和单次授权。
5. 达到像素质量和隐私/许可门槛后，再从 provider 接口、区域审核 UI、AdjustmentLayer 绑定、Agent `regionId` 工具协议依次集成；随后处理文件夹导入模式。

## 8. 决策记录与未决问题

- **已确定：** 细致分区是产品要求；至少人像/人脸重要；用户可选择不分区、粗分区、细分区，或查看 Agent 推荐；Agent 应依据区域只修改指定部分；区域和调整层/蒙版数据要可追踪、可撤销；禁止生成式重绘。
- **已确定：** 不自动导出/移动/删除；不因 RTMDet 或 SAM 有候选就默认为可靠；Agent 模型与分割工具可来自不同 provider。
- **待验证：** 首次导入默认模式、粗分区的具体类别、细分区是否默认本机、FaceParser 的最佳模型和许可链、正式 IoU/Boundary F 阈值、不同用户设备可接受延迟、建议与参数调整的确认粒度。
- **现行优先级：** 小型人工真值集 → 专用人脸解析/交互精修同图比较 → 质量门槛 → provider 接口和审核 UI → 局部调整层绑定 → Agent 目标解析 → 单张/文件夹导入体验。不要先跳到大规模 UI 集成。
