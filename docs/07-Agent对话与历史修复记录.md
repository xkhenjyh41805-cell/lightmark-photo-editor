# Agent 对话与历史修复记录

日期：2026-10-13  
范围：针对用户多轮真实模型测试截图的界面、撤销／重做与旧工具入口修复。不是新增生成式修图、自动分割或完整调整栈。

## 1. 用户反馈与处理

| 用户发现的问题 | 核实到的原因 | 本轮处理 |
| --- | --- | --- |
| 所有建议堆在全部对话末尾 | 消息列表与建议列表分开渲染，建议没有关联回复 | 每条建议关联助手消息 ID，嵌在对应回复后；旧内存记录可按同照片的消息顺序推导归属 |
| 撤销后的改动无法回来 | 历史更新跨 React updater 和微任务移交快照，存在时序风险；卡片撤销调用全局最近一步 | 抽出纯历史状态机，同步维护当前参数／past／future；卡片绑定事务 ID，只能撤销或恢复对应的最近可操作事务 |
| 已撤销操作仍显示“已执行／已采纳” | 卡片只保存最初执行结果，未读取当前历史状态 | 显示已执行、已撤销、已失效；提供“撤销此步／恢复此步”及全局“撤销上一步／重做上一步” |
| 原有步骤／专业模式看起来无效 | 只切换手动分组，但 Agent 侧栏保持显示，实际滑块仍隐藏 | 点击底部工具分组、规则提示“去调整”和显示级别时打开手动面板；切换 Agent 时退出画布局部／裁剪模式，保留已存参数 |
| 旧线性流程与 Agent 定位不一致 | 切到后面步骤就显示前面都打勾，并不代表真的修过 | 底部标注“手动调整”，去掉假完成状态；“下一步”只出现在手动工作区，本地提示标注“规则” |
| 模型主计划出现未知全局参数 | 校验发现不在白名单内的字段；截图未提供原始 JSON，不能断定具体错误字段 | 拒绝仍不改变照片；错误显示未知字段名；主进程提示补齐全部 12 个全局字段、HSL 专用工具、8 步／12 写入限制和目标绝对值规则 |

### 同时发现并修复的预览问题

- 首次载图时，图片解码结束立即调用绘制，但 Canvas 可能因“加载中”界面尚未挂载，导致空预览。现在在就绪状态提交并挂载 Canvas 后调度绘制。
- 切图时，旧异步解码回调可能污染新预览；新增取消保护。
- 图片 URL 与文件路径绑定，新照片不再临时复用上一张照片的 URL。
- 按住看原图时不把未调整的像素标记为当前编辑预览，避免给模型错误视觉上下文。
- 最近上下文包含照片标识、执行结果和事务状态；压缩模型上下文不再删掉界面上的逐轮消息与建议。

## 2. 撤销与恢复规则

1. **按照片、按历史顺序操作。** 较早卡片不能偷偷撤销较新的动作；需先按顺序撤销后续步骤。
2. 一份 Agent EditPlan 是独立事务，多参数修改一起撤销／恢复；与相邻手动滑块操作分开。
3. 连续滑块拖动仍按 800ms 窗口合并；每张照片最多保留 50 步历史。
4. 撤销后不做新编辑，可以用“恢复此步”、重做按钮或 Ctrl+Shift+Z／Ctrl+Y 恢复。
5. **撤销后发生新编辑，旧重做分支被替代。** 这是正常的历史分支规则，旧卡片会显示已失效，不再允许恢复旧分支。
6. 历史恢复不会重新调用模型，也不会重新上传照片。
7. 当前仍是会话内历史；sidecar 保存当前最终参数，不保存完整 past／future 或对话。重启后的历史不能由一份最终参数重新推导。
8. 旧版本已经丢失的重做快照无法凭截图自动重建；没有事务 ID 的旧卡片不会伪装成可安全恢复的历史。

## 4. 生效与真实照片复测

### 生效边界

- 前端开发服务正常时，界面改动可以热更新；本轮没有主动重启用户现有 Electron 窗口。
- **主进程的新工具提示词必须重启应用才会生效。** 重启之前先复制需要保留的测试对话；当前对话尚未持久化。
- 不能保证旧会话的热更新可以保留旧格式撤销历史；当前照片已经保存的参数仍通过 sidecar 读取。新版本的事务状态与恢复应以新修改验证。

### 建议复测顺序

1. “分析一下，只提建议，不要修改。”检查建议紧随这一轮，参数不变。
2. 再问一轮，检查新建议不把旧建议堆到最后。
3. 确认一条建议 → 撤销此步 → 恢复此步，观察曝光／HSL 数值与画面一起恢复。
4. “整体提亮一点。”然后使用全局撤销／重做。
5. 撤销后拖一个滑块，检查旧恢复失效，且新修改可以撤销。
6. 从 Agent 点击底部色彩／影调，操作 HSL、局部工具和预设。
7. 快速切换两张照片，检查照片名、预览和建议所属照片一致。
8. 再发送截图中曾报错的“画面偏灰”请求。如果仍有问题，记录本次错误列出的具体字段；不要放宽白名单掩盖错误。

**未在本轮验证的事项：** 新提示词对实际中转模型的遵循率、真实照片画质、不同服务商兼容性、用户真实目录写入／导出、全部裁剪拖拽与笔刷手势。模型参数校验严格拒绝仍是正常安全行为，不能保证所有模型回复必然一次通过。

## 6. 2026-10-14：模型请求超时与中转配置改进

### 截图确认的事实

用户重启后发送“图片发灰有什么办法然他更通透一些吗”，应用显示 `模型请求超时（60秒）`。调用已由主进程中止，**没有执行 EditPlan，照片没有被修改**。这不是“参数校验失败”，也没有证据表明应用发起了自动重试。

当前保存的是自定义 OpenAI 兼容地址 `https://api.taotoken.net/coding/v1`，模型 `glm-5.3-flash`。不读取、不显示也不解密 API Key。无密钥 HEAD 连通测试在约 216ms 返回 HTTP 200，但这只能证明地址可达；不证明 POST 认证、该模型支持图片、服务排队／推理速度或套餐权限正常。

TaoToken 的公开文档说明 `/coding/v1` 是 **Coding Plan 的编程场景入口**；同一个 API Key 下，`/token/v1` 与 `/v1` 属于不同计费入口。公开 Chat Completions 文档允许 `image_url` 使用 base64，但没有在该页承诺每个模型均支持视觉。因此应用只作提醒，**绝不自动将用户的 Coding Plan 地址换成 Token Plan 或按量地址**，也不自动重试。

### 已实现

- 默认超时从固定 60 秒改为 **120 秒**；模型设置可选 60／120／180／300 秒，并安全持久化。较慢模型可由用户自行延长，但延长不承诺会成功。
- 对话与“测试图文连接”均显示阶段（准备、等待响应、接收回复、解析）和已等待秒数；提供**取消请求**。
- 取消、超时、HTTP 状态错误、无效 JSON、过大响应和响应被截断显示不同的中文原因。错误中隐藏 API Key 与 `data:image` 内容，并移除 Electron 的 `Error invoking remote method` 技术前缀。
- 超时、取消、失败均不执行照片计划。失败卡片提供“按当前画面重试”，仅由用户点击触发；不自动重发。切换到其他照片后禁用这张照片的重试。
- 主进程请求状态只包含请求 ID、阶段、耗时、超时、HTTP 状态、接收字节数和错误代码；不包含 API Key、用户指令、照片 URL、对话或模型响应内容。
- 传输层禁止重定向，防止认证头随重定向发往另一地址；响应上限 300KB。

### 验证

本机 HTTP 假服务回归 12 项通过：配置边界、正常 Chat Completions、等待响应／读取正文两个超时阶段、显式取消、取消前不发请求、401 脱敏、429、网关 HTML、截断、过大响应、重定向阻止和文本块响应。

隔离 Electron UI 回归增加并通过：保存 180 秒、显示阶段和计时、取消不执行模型计划、超时不自动重试、去除 IPC 前缀、用户点击后才进行第二次重试。既有 EditPlan 27 项、Provider、历史／逐轮 8 项、几何 43 项、快照 12 项、HSL 14 项和蒙版 22 项也通过；严格 TypeScript、主进程语法和生产构建通过。上述测试仅用内存图片、固定模型回复及本机 HTTP 服务，未使用用户 API Key、未上传用户照片、未读取或改变真实图库。

### 重启后建议复测

1. 在模型设置中确认“请求超时”默认显示 120 秒；若中转站一贯偏慢，可先选择 180 秒并保存。
2. 先点“测试图文连接”。若失败，保留返回的 HTTP 状态或阶段，不要发送 API Key；若显示等待，可点“取消测试”。
3. 再向 Agent 发送一句简短、不带多轮上下文的请求。等待阶段会实时显示，超时或失败后确认照片参数没有改变。
4. 需要再次尝试时，点击失败卡片的“按当前画面重试”，确认只有这一次由用户主动发起第二个请求。
5. 若仍长期停留在“等待服务响应”，优先向中转服务商确认：Coding Plan 是否允许此模型进行图片输入、`glm-5.3-flash` 的确切视觉模型 ID、该入口和套餐是否支持当前用例。若需改到 Token Plan／按量入口，应由你确认其费用和模型名后，手动在设置中改；重新输入密钥并重新授权传图。

## 7. 2026-10-14：已有命名蒙版的局部 Agent 工具

### 目标与范围

本轮不是自动分割，也不是让模型生成坐标或笔刷。目标是先验证一条可靠的传统修图链路：**用户手动创建／修正蒙版并命名 → Agent 通过名称理解目标 → Agent 只修改该现有蒙版的传统参数 → 用户可查看、撤销、恢复。**

支持现有的渐变、径向、笔刷蒙版。用户在“调整 → 局部调整”选中蒙版后可填写不超过 32 个字符的名称，例如“天空”“黑猫主体”“右侧背景”。名称会写入该照片 sidecar，也进入原有历史记录。

### 安全约束

- 只有**启用且有非空名称**的当前照片蒙版会发送给模型；传输字段只有 `id`、`name`、`type`，不传蒙版几何、笔刷点、权重图或局部参数。
- EditPlan 新增 `adjust_mask`，必须使用当前上下文中的精确 mask ID；应用执行前再次检查该 ID 存在、属于当前照片、启用且命名。不存在、关闭、未命名、其他照片的 ID 均使整份计划拒绝，不产生半完成修改。
- 局部参数白名单为曝光、对比度、高光、阴影、白色、黑色、饱和度、自然饱和度、色温、色调。局部锐化与降噪在现有像素管线不会生效，因此明确拒绝，避免“显示已执行但没有画面效果”。
- 模型不能创建／删除／重命名蒙版，不能改变渐变／径向几何、笔刷笔触、坐标、范围或 HSL。不能编造 mask ID。
- 指令中出现“背景、天空、主体、人物、宠物、局部”等明确区域词，且没有“整体／全图／全局”等全局限定时，应用要求 plan 仅使用 `adjust_mask`，拒绝模型把它降级成 `adjust_global` 或 `set_hsl`。
- 当前没有可用命名蒙版时，应用直接解释如何创建／命名；**不发送照片预览、不调用模型**。

### 验证

- EditPlan 安全回归由 27 项扩展至 **38 项**：合法局部写入、局部不改全图、命名区域展示、未知 ID、关闭、未命名、局部锐化、非法 ID 与局部请求错误降级均覆盖。
- 既有几何 43 项、历史 12 项、HSL 14 项、蒙版算法 22 项、历史／逐轮 8 项、Provider 与传输层 12 项继续通过；严格 TypeScript、主进程语法及生产构建通过。
- 隔离 Electron UI 回归共 **42 项**：未命名局部请求不调用模型；输入名称可持久化；命名“天空”后模型只写该局部高光／曝光，全图曝光不变；局部 Agent 事务可撤销／恢复；既有 HSL、预设、裁剪、切图、超时／取消／重试仍通过。
- 所有本轮自动化验证使用内存照片、固定模型 JSON 和本机假服务；没有读取 API Key、没有上传用户照片、没有修改用户图库。

### 重启后的真实照片复测

1. 打开任意照片，进入“调整 → 局部调整”，用渐变、径向或笔刷创建目标范围；先用 Alt 检查红色蒙版范围。
2. 将它命名为与真实语义对应的名称，例如“天空”或“右侧背景”，并保持启用。切回 Agent 后应出现“可用局部蒙版”。
3. 发送“压暗天空一点，保留云层细节”。期望执行卡只显示“天空 · 高光／曝光”等局部变更，画布只有蒙版范围变化。
4. 点击“撤销此步”与“恢复此步”，确认局部参数和画面同步回退／恢复，全局滑块不变。
5. 将名称清空或关闭蒙版，再发送同一句；期望应用提示命名／启用，不调用模型，也不改全图。
6. 创建名为“主体”的蒙版后问“压暗天空”；若模型找不到对应语义，应只澄清或不生成计划，不能任意改“主体”。这是待真实多模态模型验证的行为边界。

**下一步仍是自动蒙版 POC，而不是直接扩大到任意物体或批次。** 先用分割模型生成候选 mask、让用户校正和命名，再复用本节已经验证的 `adjust_mask` 执行门禁。

## 8. 2026-10-14：本地自动天空候选蒙版 POC

### 实现范围

- 在“调整 → 局部调整”加入“生成天空候选蒙版”。首次点击下载／缓存公开语义分割模型；推理在 Electron 渲染进程的 Web Worker 中运行，使用 CPU/WASM `q8` 路径，不调用 Python、CUDA、BYOM 或中转 API。
- 模型输出保存为最多 512px 边长的单通道栅格权重图，随照片 sidecar 和历史记录持久化；预览与全分辨率导出按归一化坐标缩放，用户绘制／擦除的笔触叠加在候选上。
- 创建结果是**禁用的待确认候选**。用户按 `Alt` 看红色覆盖，可笔刷修正；仅“接受候选并启用”后，候选才变为命名的“天空”蒙版。拒绝会删除候选。
- 待确认候选不影响画面、不导出、不传给 Agent；渲染层筛选、主进程局部上下文以及 `prepareEditPlan` 三层均再次阻止 `adjust_mask` 访问。采纳后才只传 `id`、名称和类型，仍不传几何、笔触或栅格数据。

### 实际模型验证与兼容约束
