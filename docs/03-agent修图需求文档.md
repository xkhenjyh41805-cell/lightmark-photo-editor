# 光印 LightMark — 非生成式修图 Agent 需求文档

> 版本：v0.6（已接入 BYOM、已有命名蒙版局部工具与本地天空候选 POC）  
> 日期：2026-10-14  
> 状态：单图对话、全局工具、已有命名蒙版局部工具和本地天空候选 POC 已实现；人物／宠物／背景分割、参考图风格、批量与移动端范围仍需验证  
> 产品方向：由 Agent 调用传统图像处理工具，不生成或重绘照片像素

## 1. 产品定义

LightMark Agent 是集成在修图工作台侧栏里的对话式修图 Agent。用户围绕当前照片与 AI 多轮沟通；Agent 使用多模态模型理解图像和意图，调用 LightMark 现有的非生成式工具主动执行安全调整，也会解释结果并提出可采纳的后续建议。用户可追问、微调、接受建议或撤销。

**首版交互原则：用户通过对话表达目标，Agent 主动修图，也主动给出建议；执行结果非破坏、可查看、可微调、可撤销。**已执行操作与尚未执行建议必须分开显示。首版先验证主动修，未来再加入建议模式等选项。

这里的“Agent”不是生成式图片模型。MVP 不调用文生图、图生图、局部重绘、生成式填充或 AI 换景；它通过传统图像算法、调整参数和经用户确认的蒙版处理原照片。参考图风格匹配是后续候选：提取可表达为调整参数的色调／色彩特征，不复制参考图内容或像素。

## 2. 当前项目基础

项目已有 Electron、React、TypeScript 桌面应用，以及以下可复用能力：

- 曝光、对比度、高光、阴影、白色、黑色、饱和度、自然饱和度、锐化、降噪、色温和色调等全局调整。
- 渐变、径向和笔刷蒙版；本地语义分割的天空候选可在用户检查、笔刷修正与采纳后成为传统局部蒙版。
- HSL 分色、预设、裁剪、旋转、实时预览、直方图和高分辨率导出。
- sidecar 参数持久化、撤销／重做和原图保留。
- 基于直方图与参数的本地规则建议引擎。

当前已接入可配置 Base URL 的 OpenAI 兼容 BYOM 多模态接口，并以受限 EditPlan 调用全局、HSL 与已有命名蒙版工具；API Key 仅留在 Electron 主进程安全存储。不同服务商的模型 ID、图片能力和套餐权限仍需逐项真实联调。已实现仅天空的本地语义分割候选 POC：模型下载与推理在设备 Worker 中完成，用户检查／笔刷修正／采纳后才成为可用蒙版；尚无人像、宠物或背景的自动语义蒙版能力。

## 3. 目标用户与产品兼容性

**主要用户：**会拍照但不太会修图的摄影爱好者。产品默认需要少操作、能理解用户自然语言，并解释主要调整。

**兼容用户：**希望掌控具体参数和局部调整的专业摄影师／修图师。专业能力应可渐进展开，不通过降低画质或破坏原始参数结构来简化入门体验。

**核心问题：**用户知道自己想让照片“自然一点”“亮一点”或“背景暗一点”，但不容易把目标翻译成具体滑块、调整顺序和区域蒙版。

**用户收益：**可用自然对话让 Agent 执行修图并提出下一步建议；不必先研究每个滑块；同时能看到实际改了什么，并保留手动微调、接受／拒绝建议、撤销和专业控制权。

## 4. 产品目标与非目标

### 目标

1. Agent 位于现有工作台侧栏，与照片预览及调整面板并存。
2. 用户通过自然语言发起任务；首版默认主动执行安全的非破坏式参数调整。
3. Agent 通过用户接入的多模态模型理解指令与照片；后续支持产品自带模型时，仍保留用户自接模型能力。
4. Agent 仅能调用白名单内的本地图像工具，显示执行摘要和逐项参数。
5. 用户可在结果上继续手动调整、对比前后、撤销 Agent 本次操作。
6. 原图不得被覆盖；导出必须由用户主动触发。
7. 评估自动区域选择与语义蒙版的可行性，但不为了“Agent 感”而牺牲蒙版质量。

### 非目标（MVP 不做）

- 生成、重绘或替换图像内容，包括生成式补图、换背景、换天空、生成式磨皮。
- Agent 自主导出、覆盖原文件、无检查地批量执行或运行任意脚本／系统命令。
- 将 VLM 输出的点、框或文字区域直接当成高精度软蒙版使用。
- Photoshop 插件或桌面自动化联动。
- 多 Agent、RAG 知识库和隐藏的长期记忆。

## 5. 核心单张修图流程

1. 用户新建工作组并一次导入一组照片，或打开已有工作组；每个工作组代表一次持续修图工作。
2. 用户在侧栏输入自然语言目标，例如“整体提亮一些，颜色自然，别把黑猫的暗部提得发灰”。
3. 若尚未接入多模态模型，软件先引导用户完成模型设置，不伪装成真实模型修图。
4. 对“压暗天空”等当前已支持、明确且单一的局部目标，Agent 先复用已有同名蒙版；缺失时在本机调用分割工具生成**临时天空蒙版**。只有选区成功后，才按用户授权将缩小预览和该蒙版的最小描述交给所选多模态模型生成受限计划。
5. 应用端验证 schema、工具白名单、参数边界、照片版本和临时蒙版 ID。若计划没有引用自动选取的目标、局部语义不确定、选区失败或操作不支持，则不创建／保存蒙版并停止或澄清，不猜测执行。
6. 对可安全自动执行的全局或局部调整，Agent 直接调用现有图像管线，把变更应用为当前照片的非破坏式编辑状态；自动蒙版和该次局部参数须作为**同一撤销事务**写入。
7. 侧栏显示结果摘要、参数变化和“撤销本次修图”；主画布展示处理结果，用户可继续调整。
8. 用户单独决定是否导出。未经用户操作不覆盖原图或触发批量导出。

## 6. 功能需求

### FR-01 侧栏自然语言入口（P0）

在现有桌面修图界面中提供常驻或可展开的 Agent 侧栏。一次导入的一组照片创建一个持久工作组和一段对话；在组内切换照片时沿用该对话，不为每张照片拆分会话；切换到其他工作组时恢复该组自己的对话。清空对话只影响当前工作组。输入框支持自然语言、多轮对话与基于前序调整的微调，例如“再自然一点”或“阴影恢复一些”。接近模型上下文上限时自动压缩较早对话，保留当前照片、关键编辑、用户目标和待确认建议；若压缩后信息不足，先澄清而不猜测。Agent 可在执行用户目标后另行提出有理由的后续建议。已执行结果、待确认建议和澄清问题必须有不同状态。模型不可用、网络超时或额度受限时应明确提示，并允许用户继续手动修图。

### FR-02 用户自接多模态模型（P0）

首版采用 BYOM（Bring Your Own Model，用户自带模型）方式。用户在设置中配置支持图像输入的多模态模型及其凭据；应用在保存配置前提供连接测试和能力提示。后续如提供产品内置模型，应通过相同的 `VisionProvider` 抽象接入，不能移除或降级用户自接模型选项。

模型配置可以采用“常见提供方预设 + 可选兼容接口地址、模型名”的方式。具体协议与首批提供方待决定。API Key 不得进入 renderer bundle、日志或普通配置文件，应由 Electron 主进程调用，并安全保存于操作系统凭据存储区。首次云端传图前明确告知用户数据去向和传输内容，并询问授权；首次授权可勾选“记住选择／不再询问”。未勾选时每次请求前继续询问；记住的授权可随时在设置中撤销／关闭。默认只传满足理解任务所需的缩放预览，不上传原始高分辨率文件，除非未来功能明确需要并单独征求同意。

### FR-03 受限计划与工具调用（P0）

模型输出只能是结构化编辑计划，应用端再映射到本地工具注册表。模型不得传入可执行代码、文件路径、系统命令、任意像素数据或未注册的工具名。

首批全局工具包括：

- `adjust_global`：只接收 `AdjustParams` 已定义字段。
- `set_hsl`：只接收项目既有 HSL 色段字段。
- `inspect_histogram`：只读直方图和本地参数，可给出建议，不直接改图。

已实现的局部工具为 `adjust_mask`：只接收**当前照片中已采纳、启用且由用户命名**的真实 mask ID 与局部传统参数（曝光、对比度、高光、阴影、白色、黑色、饱和度、自然饱和度、色温、色调）。应用只将 mask 的 ID、名称和类型发送给模型，不发送几何、笔触、栅格权重或原始局部参数；执行时再次检查该 mask 仍存在、已采纳、启用且有名称。模型不能创建／删除／重命名蒙版，不能传坐标、范围、笔触或图层数据，不能修改不支持的局部锐化／降噪。

用户明确说“天空”“背景”“主体”“局部”等区域词时，应用不得把请求静默降级为全图调整。已实现的“天空”路径会先复用已有同语义蒙版；没有时由 Agent 在**本机**调用语义分割创建内存中的临时天空蒙版，选区失败则不上传照片、不调用模型也不改图。模型只能引用上下文给出的精确 ID；对于临时天空蒙版，应用端在提交前再次要求整份计划确实写入该 ID，否则蒙版不保存。其余未支持的背景／主体／人物／宠物目标仍提示用户创建或选择命名蒙版。ID 不存在、已关闭、未命名或对应错误区域时整份计划拒绝且不改图；模型不得自行编造坐标蒙版。

示意数据：

```json
{
  "version": 1,
  "summary": "提亮整体并保留暗部细节",
  "steps": [
    {
      "tool": "adjust_global",
      "args": { "exposure": 10, "shadows": 7 },
      "reason": "整体亮度略低，适度打开暗部"
    }
  ]
}
```

数值范围以 `src/image/index.ts` 中的类型和算法约束为准，并由应用端二次校验。模型输出不是可直接执行的可信指令。

### FR-04 主动执行、结果查看与撤销（P0）

用户通过对话明确表达目标后，Agent 对经过白名单和范围校验的安全调整直接执行，无需再要求用户逐步点击“确认计划”。主画布更新为当前非破坏式结果；侧栏显示变更摘要、参数值和原因。Agent 还可主动提出独立的后续建议；每条建议须说明观察到的现象、影响区域和建议理由（例如“这部分画面偏暗，建议提亮阴影”），并在用户明确确认后才执行。建议不得冒充已执行操作；用户可逐项采纳／拒绝、继续对话、通过滑块调整，或一键撤销 Agent 本次整组操作。

以下情形不能静默主动执行：区域选择不确定、模型要求生成式编辑、计划超过安全限制、无法回滚的文件操作、导出／覆盖、批次级大范围修改。系统应追问或要求确认。默认仅操作当前选中照片。

### FR-05 执行状态与失败恢复（P0）

界面至少显示：等待指令、分析照片、准备工具计划、正在调整、已完成（可撤销）、失败／需要补充信息。超时、模型格式错误或图像处理失败时，照片状态回到执行前快照；不得保存半完成状态。

### FR-06 局部蒙版与语义区域绑定（P1）

**P1a（已实现）：**用户用渐变、径向或笔刷创建区域，并命名为例如“天空”“黑猫主体”“右侧背景”。Agent 获得启用且命名的区域清单，理解明确请求后只可引用该 mask ID 执行局部传统工具；执行摘要显示蒙版名称与参数，整组事务可撤销／恢复。未命名、关闭、缺失或其他照片的 mask 均不可被引用。

**P1b（天空自动调度已实现）：**本地已实现“天空候选”。普通对话中，用户直接说“压暗天空、保留云层细节”即可：Agent 优先复用已有天空蒙版；不存在时在 Electron Worker 中下载／缓存模型、创建**内存临时**栅格蒙版，并将“蒙版创建 + `adjust_mask` 参数”作为一次原子事务提交。模型若不引用这张临时天空蒙版，应用拒绝计划且不保存蒙版。结果卡说明“已自动选取天空”，并提供“查看／修正范围”和整步撤销；撤销会同时移除自动蒙版与局部参数，恢复则一并恢复。手动入口仍保留：用户可按 `Alt` 检查红色范围、笔刷补画／擦除、手动采纳候选；它是专业控制和不确定场景的兜底，而非普通用户的前置步骤。该天空 POC 不改变产品验证优先级：**人物 → 宠物 → 背景 → 天空**。其余目标若存在多个相似对象、mask 缺失或语义对应不确定，Agent 应追问或要求用户点选，不得猜测，也不得降级成全图调整。详见 [08-本地自动天空候选蒙版POC](08-本地自动天空候选蒙版POC.md)。

多模态模型负责理解用户指令和语义类别；像素级边缘、毛发、半透明和前后景分界仍需专门的分割工具。不能假设通用 VLM 单独输出的区域框就是可用蒙版。建议验证 VLM／文本定位给出目标或点框提示 → 分割工具生成可命名 mask → Agent 将自然语言目标绑定至真实 mask ID → 局部参数工具执行并显示实际区域。支持 SAM 2 一类的可提示图像分割模型；文本到目标定位可研究 Grounded SAM 2 这类“文本 grounding + SAM 分割”组合。[1] [2]

SAM 2 官方支持点、框或已有 mask 提示，并允许用额外提示修正 mask；它是分割工具，不是生成式修图模型。[1] Grounded SAM 2 展示了用文本定位和 SAM 分割串接的实现。[2] 因此 Agent 负责理解目标和选择对应区域，分割模型负责像素 mask。质量验证仍必要，但暂不把固定数值阈值设成产品交互门槛；内部需测试误选率、边缘修整时间和设备性能。SAM 2 官方仓库当前安装说明涉及 Python、PyTorch 和 CUDA；在 Windows 上建议 WSL，因此不建议首版把它硬塞进 Electron 安装包。[3]

P1 验证集按上述优先顺序覆盖人物、宠物、背景与天空，并包含头发／动物毛发、遮挡、相近颜色背景和多个相似对象。错误或歧义区域必须可以切换、修整或撤销。

**P1c（人物选区技术预研已完成，尚未实现）：**技术方案、验收门槛与候选部署／许可比较见 [P1c 人物自动选区技术方案](09-P1c人物自动选区技术方案.md)。

**P1c 首轮实测结论（2026-10-18）：**已用公开单人、多人和无人物样例测试 DETR panoptic q8 与现有 SegFormer ADE20K q8；两者均未达到自动修图质量门槛。DETR 对单人照片产生整幅 `person` mask；SegFormer 在猫咪负样例误报大面积 `person` 区域，且多人场景只能输出合并语义蒙版。当前不开放人物自动路由或自动应用，继续保留手动蒙版；下一步先评估其它本地分割候选。测试环境、耗时、可视化及复跑命令见 [P1c 人物自动选区技术方案](09-P1c人物自动选区技术方案.md)。

### FR-07 专业兼容（P1）

首版不强迫新手面对复杂控件，但执行摘要要能打开查看详细参数。后续“建议模式”与“主动修模式”可作为同一 Agent 侧栏中的交互模式，而非拆成两套应用；专业用户可选择逐步确认、修改参数和禁用特定工具。

### FR-08 批次修图（后续产品能力）

批量修图建议设计为 **“批次工作区 + 可复用批次配方 + Agent 内部技能”**，不建议只做一个叫“批量 Skill”的入口：

当前持久工作组只代表“一次工作的一组照片 + 一段 Agent 对话”，用于持续修图与恢复上下文；它不包含连拍聚类、筛片状态、近似图比较或批次配方，不能视为 FR-08 已完成。

- **批次工作区（用户可见的功能／页面）：**管理一次拍摄的照片集合、分组、处理状态、异常照片和最终检查。
- **批次配方（用户可见、可编辑、可复用）：**描述一个批次的处理顺序和选项，例如“粗筛 → 按相似场景分组 → 统一风格 → 单张曝光微调 → 人工检查 → 导出”。配方版本化、可预览，并设置哪些步骤自动执行、哪些步骤需用户审核。
- **Agent Skills（内部可组合的工作单元）：**例如粗筛推荐、相似照片分组、建立参考片风格、逐张曝光／白平衡归一、检查异常、生成审核清单。每个技能有结构化输入输出、允许调用的工具和停止条件；不是执行任意脚本的插件。

推荐的批次流程：导入拍摄批次 → 按近重复／连拍分组并提供并排比较和最佳候选 → Agent 标出模糊、曝光异常、闭眼／表情等可解释提示 → 摄影者确认保留集 → 将相似光线和场景分组 → 选择统一全局参数或逐图白平衡／曝光归一策略 → 逐张查看异常并确认修图状态。闭眼是提示而非自动淘汰规则：合照不能因一人闭眼就默认淘汰整张，且应允许保留刻意闭眼或有表达意图的照片。状态至少区分待筛选、推荐入选／最佳候选、已确认保留、待修、已修和需复核；筛选状态与修图状态分别记录。

首版暂不支持批次级主动修改。批次功能应在单张 Agent 的计划校验、回滚、撤销和效果评估稳定后再做；批次执行需支持暂停、跳过、失败重试、逐张撤回和最终审核。默认不自动删除、移动或导出原片。调研建议首个批次编辑版本先对用户确认的选择集应用统一全局参数配方；逐图白平衡／曝光归一作为可选试验，逐图展示变化并将离群项交人工复核，最终范围待产品评审。

### FR-09 参考图风格匹配（P2，后续验证）

用户可选择一张参考照片和当前目标照片，请 Agent 分析参考图中可由 LightMark 现有工具表达的影调、对比度、白平衡、饱和度与 HSL 等特征，并生成可编辑的 `StyleRecipe`。用户可调整匹配强度、预览目标图前后效果、逐项修改／撤销，并可将确认后的参数另存为预设。

该功能是“从参考图提取可解释的参数建议并应用传统调整”，不是图生图或生成式风格迁移：不得复制对象、背景、构图或像素内容；不支持的特征应说明无法可靠映射，不可编造参数。首版不包含此能力，需先用跨场景参考图样本评估风格特征与场景内容是否能区分。

### FR-10 非破坏式调整栈（P1）

全局参数、局部蒙版和 Agent／手动操作可作为独立、可读的调整项展示。每项至少记录名称、作用区域、参数、来源和撤销关系；用户可显隐对比、微调、删除／恢复并查看本次 Agent 整组操作。首版沿用确定的图像处理顺序，不提供任意图层重排、像素混合模式或复杂合成；后续如加入传统像素修复工具，再评估独立的修复图层。

## 7. Agent 与工具架构建议

```text
侧栏自然语言指令 + 当前照片预览
  → VisionProvider（BYOM 多模态；未来可切内置提供方）
  → 受限 Intent / EditPlan
  → schema 校验 + 工具白名单 + 数值边界 + 风险判断
  → 本地工具注册表分派
  → processPhoto / applyAdjustments / applyWithMasks
  → 非破坏式当前编辑状态 + 历史快照
  → 结果摘要、参数面板、前后对比与撤销
```

蒙版能力独立为 `MaskProvider`：输入是目标描述／点／框和照片预览，输出为可编辑的 mask；不与生成式图像模型耦合。批次能力未来可由 Batch Orchestrator 编排可恢复的配方节点及内部 Agent Skills。

`AdjustmentStack`／`AdjustmentNode` 将全局参数、具名局部 mask、编辑来源（用户／Agent／配方）、显隐状态和历史事务组织为非破坏式记录；它是参数编辑栈，不等同 Photoshop 像素图层或混合模式系统。

首版不必引入 Agent 框架。先在 TypeScript 中手写受限的计划生成与工具循环；模型可修正格式错误一次，仍不合法就给用户解释。模型 API、UI 和图像引擎彼此分离。API Key 从 Electron 主进程安全读取；renderer 仅接收已清理的状态和参数。

## 8. 非功能要求

- **非破坏性：**Agent 不覆盖原图；复用 PhotoAdjust／sidecar 和历史机制。
- **可逆：**一次 Agent 执行作为一条可撤销事务，不与用户此前编辑混成无法拆分的一步。
- **可解释：**显示调整摘要、工具名和关键参数；专业用户可展开详细计划。
- **受控：**主动执行仅限当前照片的安全白名单工具；导出、覆盖和批次级操作仍由用户发起。
- **隐私：**首次云端传图前明确授权，可选记住授权／不再询问；已记住授权可在设置中撤销；支持删除模型配置和凭据；日志不得写入照片或密钥。
- **兼容：**不破坏现有手动修图、sidecar 格式、预设和撤销／重做。
- **可扩展：**模型接入采用 Provider Adapter；语义 mask 使用独立分割接口；将来加入内置模型不影响 BYOM。为未来移动端预留平台适配边界：编辑协议和纯 TypeScript 业务逻辑尽量不依赖 Electron／DOM，照片访问、图像渲染、凭据、存储和导出通过平台接口隔离；不假设现有桌面 UI、Canvas 或 Sharp 可直接复用。

## 9. MVP 验收标准
1. 用户配置一个支持图像输入的多模态模型，连接测试成功后可对当前照片发出自然语言指令。
2. 对“提亮／压暗、对比度、饱和度、白平衡”等安全全局指令，模型计划经过校验后自动应用到当前编辑状态，并显示调整摘要。
3. 越界参数、未知工具、代码、文件路径或不支持的生成式意图不得执行。
4. 一个撤销动作能完整回滚 Agent 本次事务；多轮后仍能与用户手动调整分别撤销。
5. 局部语义指令优先由 Agent 将自然语言目标绑定到对应命名 mask；区域歧义、缺失或未通过内部验证时，系统请求澄清／用户选择，不得误用全局调整。清晰、无歧义的区域不要求重复确认，但必须显示实际作用区域且可切换、修整和撤销。
6. 原始文件不变；导出必须由用户主动触发。
7. 至少 20 条固定指令做回归测试，记录工具选择正确率、参数校验通过率、撤销成功率、用户改参数比例及失败率。
8. 无接入模型时清楚显示未连接状态；不使用静态规则假装多模态能力已工作。
9. 不接生成式图像模型，不调用任何生成／重绘能力。

## 10. 版本路线

- **交互原型：**验证侧栏、主动修后的摘要、参数微调、前后对比和一键撤销；原型不调用真实模型或图像算法。
- **MVP-A：**固定 EditPlan 接入项目真实图像管线；验证自动执行、一次事务撤销和 sidecar 兼容。
- **MVP-B：**加入用户自接多模态模型、连接测试、密钥安全保存、图片上传授权和结构化计划校验。
- **P1 蒙版验证：**对比 VLM/grounding + SAM 类分割管线与手绘蒙版；按质量门槛决定是否产品化。
- **P1 调整栈：**将全局参数、局部蒙版和 Agent 操作可见化为独立、可撤销的非破坏式调整项；不实现完整 Photoshop 式像素图层／混合模式。
- **后续交互模式：**加入主动修／建议模式切换，保持相同工具层与编辑数据模型。
- **移动端 POC（桌面单图 Agent 稳定后）：**先验证手机伴随版，支持本机选图、快速筛选、主动修全局参数和导出；是否扩展为完整移动修图另行评估。复用平台无关的 EditPlan／参数协议，不假设复用 Electron 视图或文件实现。
- **参考图风格匹配（P2）：**在 Agent 主动修稳定后，验证参考图 → 参数化 `StyleRecipe` → 目标图预览／微调的非生成式流程；先评测，不预设模型能准确抽取风格。
- **批次版本：**在单图稳定后增加批次工作区和配方；内部按 Skills 编排，但所有批量执行可预览、暂停、回滚和审阅。

## 11. 仍需确认的问题
1. 首批模型接入要优先支持哪些类型：OpenAI 兼容接口（自定义 Base URL／模型名）还是若干官方厂商各自的原生接口？建议第一版先选 1–2 种可测试协议，避免空泛支持“任意模型”。
2. 首次云端传图授权的“记住选择／不再询问”如何展示及撤销；已确定首次询问，并允许用户选择是否记住。
3. 主动修首版是否只做全局调整，还是加入用户手绘蒙版；自动语义蒙版作为 P1 验证，先按人物→宠物→背景→天空评估。
4. 批次首版建议先同步统一全局参数；是否同时加入逐图白平衡／曝光归一试验仍待评审。筛片信号只作建议，保留集仍由摄影者决定。
5. 用户自接模型失败时，首版是否允许规则建议继续工作？建议保留本地规则提示，但明确标注“规则建议”，不伪装成 Agent 执行。
6. 手机首期定位是轻量伴随版，还是完整独立修图器？建议先做选图、筛选、全局参数建议和导出的伴随版 POC，再根据使用反馈决定是否扩展专业编辑和桌面同步。
7. 参考图风格匹配首期要覆盖哪些维度（仅全局色调／色彩，还是也包括局部蒙版）？建议先只生成现有全局参数和 HSL 可表达的 `StyleRecipe`，避免风格迁移变成内容生成。
