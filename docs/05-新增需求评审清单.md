# 光印 LightMark — 新增需求评审清单

> 日期：2026-10-13  
> 状态：**供产品负责人评审，不代表所有候选需求已批准进入首版**  
> 背景：结合本轮竞品／图像工具调研、此前移动端讨论，以及你刚提出的对话式 Agent 与参考图方向整理。详细依据和实施路线见[竞品调研与 Agent 实施计划](./04-竞品调研与Agent实施计划.md)。

## A. 你刚确认的产品方向

### A1. 对话式修图 Agent（核心理念更新，确认）

用户通过自然对话说明目标，Agent 理解当前照片和上下文，调用白名单内的传统修图工具执行安全调整；同时解释已做的修改，并可主动提出下一步建议。用户可以继续沟通、微调、接受／拒绝建议或撤销。

**需求边界：**“AI 来改”是 Agent 操作现有参数／蒙版工具，不是生成新图片。已执行动作和未执行建议须分开呈现；不清楚或高风险的动作应追问／请求确认。

### A2. 参考图风格匹配（后续方向，详细范围待评审）

用户选择一张参考图和一张目标图。Agent 分析参考图中可由现有参数表达的影调、对比、色温／色调、饱和度与 HSL 特征，生成可编辑的 `StyleRecipe`，在目标图上预览并允许调节匹配强度、逐项微调、接受／撤销。

**明确不做：**图生图、像素复制、主体／背景内容替换或自动换景。无法可靠转成现有参数的视觉效果，应说明无法匹配，不应假装已经复刻。建议排在对话式单图 Agent 稳定之后，先评测再决定是否产品化。

## B. 调研提出／补强的候选需求（请确认优先级）

### B1. 主动执行与建议分开管理（建议 P0）

- 用户明确要求且通过白名单、参数范围和风险校验的操作可以主动应用。
- Agent 主动发现的优化方向必须作为独立建议展示，说明观察到的现象、影响区域和建议理由；这类建议在用户确认前不得执行。
- 每项执行显示意图、作用范围、参数变化和理由；可预览、微调、撤销。

**验收观察点：**例如 Agent 应能说明“这部分画面偏暗，所以建议提亮阴影”；用户能区分已执行调整与待确认建议；未获用户确认的主动建议不会改图；一次撤销能回滚该轮 Agent 操作。

### B2. 工作区级连续对话与自动压缩上下文（建议 P0）

切换照片时不创建独立对话；“再自然一点”“暗部再亮一些”应依据当前选中照片和已执行编辑继续调整。对话上下文属于当前工作区；接近模型上下文上限时自动压缩较早的对话，保留当前照片、已做调整、用户目标、重要偏好及待确认事项，不默认建立隐藏的长期记忆。

自动压缩后如果缺少完成当前操作所需的信息，Agent 应先澄清，不可臆测。无需为每张照片单独维护对话或单独清空对话记录。

### B3. 蒙版需是可见、可编辑、可审阅对象（研究补强，建议 P1 验证）

期望 Agent 能自动生成／整理可命名的区域蒙版，并把用户说的“人物”“宠物”“背景”“天空”等目标映射到对应蒙版，再调用局部传统工具。已知首批验证顺序为：**人物 → 宠物 → 背景 → 天空**。界面应显示实际作用区域并支持切换、修正或撤销；多个相似对象或区域理解不确定时先追问。暂不预设一个固定的产品数值门槛，先用代表性照片验证分割质量、速度及误选率，再确定内部上线标准。

Agent 需要先把用户的语义目标绑定到真实 mask ID；不得将未验证的文字框直接当作像素蒙版。自动蒙版质量仍需测试，但不要求用户对每一个清晰、无歧义的选区重复确认。

### B4. 批次功能采用三层组合（研究建议，建议 P2）

- **批次工作区：**面向用户的一组照片、筛选条件、目标选择、处理状态和异常列表。
- **批次配方：**保存已确认的参数流程与适用范围，执行前显示目标张数及将同步的设置。
- **内部 Skills：**筛选建议、近重复候选、逐图调整、异常检查等有结构化输入输出和停止条件的能力；不作为可运行任意脚本的插件。

**明确边界：**默认不自动删除、移动或导出照片。**待评估：**首个批次版本只做统一全局参数，还是同时验证逐图白平衡／曝光归一；批次专项调研后再定。

### B5. 批次筛选与局部参数要逐图验证（研究建议，建议 P2）

初期用评级、旗标、元数据、清晰度／曝光异常和近重复候选协助粗筛；对连拍或近似照片提供并排／逐张比较及“最佳候选”建议，最终保留集由摄影者确认。闭眼、表情等只能作为可解释的提示：合照中不能因一个人闭眼就默认淘汰整张；也要允许用户保留刻意闭眼或有表达意图的照片。批量同步要明确选择设置类别；局部蒙版不可复制参考图坐标，必须逐图重新推理并处理歧义。

**验收观察点：**目标照片数和例外可见；筛片理由可读、用户可覆盖；近重复组能比较并标出最佳候选；误筛不自动删片；局部区域必须逐图绑定到正确主体／背景区域。

### B6. 批量任务可暂停、取消并隔离失败（研究建议，建议 P2）

队列显示总进度及每张状态，支持暂停／继续、跳过、失败重试、逐张撤回；单张失败不应中断整批。照片至少区分“待筛选、推荐入选／最佳候选、已确认保留、待修、已修、需复核”等状态，筛选状态与修图状态分开记录，避免用一个标签混淆。导出仍由用户主动启动。

### B7. BYOM 隐私和权限作为产品功能（研究补强，建议 P0）

显示模型服务和图像数据去向；标清发送原图还是缩放预览、EXIF 等元数据是否包含；云端图像处理要有授权与关闭路径。密钥使用系统安全存储，日志不写入密钥或照片内容。

**已确认：**首次云端传图前明确授权；首次授权界面提供“记住选择／不再询问”选项。未勾选时按请求询问；已记住的授权可在设置中随时撤销／关闭，并清楚显示当前授权状态和数据去向。

### B8. 移动端先做伴随版 POC（你之前提出，建议 P2）

桌面单图 Agent 稳定后，验证手机选图、快速筛选、全局参数建议、预览／撤销和本机导出。完整局部蒙版、RAW 全格式、批量修图和桌面同步暂不承诺；先评估 React Native／Expo 与 PWA，并区分可复用的纯业务逻辑和需重写的平台 UI／文件处理。

### B9. 做“调整栈”，不做完整 Photoshop 式图层（调研建议，建议 P1）

把全局参数、局部蒙版和 Agent／手动调整作为独立、可读的非破坏式编辑单元。每项能显示名称、作用区域、参数及来源；支持显隐对比、微调、删除／恢复和撤销。目标是让用户看懂并控制 Agent 改了哪一块，不是首版就实现像素图层、任意混合模式或复杂合成。调整项是否允许自由重排可后续验证，首版应避免改变现有图像处理顺序而造成结果漂移。

## C. 建议的实施优先顺序

1. **先确认产品行为：**对话式 Agent、主动执行与建议的区分、用户确认／撤销边界。
2. **先做可交付 MVP：**白名单工具、参数校验、事务回滚、BYOM 多模态模型、侧栏多轮对话和安全的全局调整。
3. **完善非破坏式编辑栈：**让全局调整、局部蒙版和 Agent 操作成为可见、可控、可撤销的编辑单元；不扩张为 Photoshop 合成层。
4. **单独验证区域能力：**语义蒙版按人物→宠物→背景→天空顺序测试；清晰区域可由 Agent 自动绑定，歧义时追问，质量不足时不产品化。
5. **单图稳定后做批次工作区：**先近似组、并排比较、候选最佳与人工筛片状态；再验证全局参数配方；逐图白平衡／曝光归一作为可选试验，所有输出可复核、可撤销。
6. **其他后续特性：**参考图风格匹配 POC、手机伴随版 POC，依用户价值和开发资源决定先后。

## D. 请你评审的重点

- A1 是否准确体现了 Agent 解释观察到的现象和修改原因，并且主动提出的建议必须由用户确认后才执行？
- A2 参考图风格匹配是否限定为现有参数可表达的影调／色彩，而不做生成式迁移？
- B2 是否准确体现“切换照片不另开对话、上下文满时自动压缩”？
- B3 的自动蒙版语义绑定顺序（人物→宠物→背景→天空）是否正确？是否接受不要求每个清晰选区都重复确认？
- B4–B6 的批次范围、连拍最佳候选、闭眼提示、状态分层及“不自动删除／移动／导出”边界是否符合你的想法？
- B9 是否同意先做非破坏式“调整栈”，而不实现完整 Photoshop 式像素图层与混合模式？
- P2 里参考图、手机伴随版、批量功能的先后优先级是否需要调整？
